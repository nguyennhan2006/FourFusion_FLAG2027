# src/: verbatim source copies (read-only reference)

This folder holds byte-for-byte copies of the builders, notebook modules, local scripts and chain scripts of the
FourFusion team repository, at their original relative paths (`kaggle/`, `Experiment/`, `BEST/`, `release/`).
`SRC_MANIFEST.json` lists every file with its sha256, md5, size, line endings, git status in the team repository,
role, the pipeline stages that use it (`files[].stages`, reverse index `by_stage`) and the versions of it that
actually ran (`files[].executed_versions`).

**Nothing in src/ is executed by the runner.** Each stage under `stages/` carries the code that actually ran: the
executed notebook (or the local script, with every change listed in the stage's `CHANGES.md`). src/ is for reading,
for checking the code embedded in executed notebooks, and for regenerating notebooks with their builders.

## Executed code versus these copies

Most of the team repository was never committed (`git.status` = `untracked`) and many files changed after the runs.
`files[].executed_versions` has three kinds of entries (`origin`):

- `stage-scan`: found by `_tools/scan_stage_code.py`, which compares the copies with every executed copy kept under
  `stages/<group>/<id>/original/`: decoded / embedded payload files, base64, gzip, zlib and zip blobs in the code cells
  of the executed notebooks, source text kept in string constants (`CORE_SOURCE = '...'`, `SRC_<PATH> = r'''...'''`),
  and modules pasted as a cell. Each entry gives the full sha256 (and md5), the stages, where the bytes are in this
  repository (`in_repo`), `match` (`exact`, `lf-equal` = equal after CRLF -> LF, `same-lines` = only the final newline
  differs, `differs`) and, for a difference, a diff summary from the executed bytes to this copy. Copies found in
  evidence runs, staging folders, builder-regenerated notebooks or a stage's own runnable copy are listed separately in
  `files[].other_copies_in_repo`.
- `citation`: a hash read from a `CODE_MD5` dictionary or a build document (layer map). A citation whose hash equals a
  scan entry is folded into it (`citations`).
- `claim`: a statement without a hash (local scripts, patch-time inputs).

The scan only sees what the stage packages kept. A stage whose notebook was regenerated from a builder
(`origin.exactness` = `builder-regenerated`, e.g. `f10_models`, `f12_eval_feats`, `t154_g1_*`) has no executed copy, so a
missing `stage-scan` entry is not proof that this copy ran. `summary.files_with_a_differing_executed_version` lists every
file with at least one executed version that is not this copy; `stage_scan.unmapped_payloads` lists code payloads of
executed notebooks that are not in src/ (entry scripts generated by the builders).

## Defaults that read dev data

Several copied modules and builders read the dev lists when run as they are. The stages of the 13.54 chain patch them
(DESIGN 2.8 / G11; each patch is a `dev-exclusion` row in the stage's `CHANGES.md`). Do not run them unpatched:

| file | default | stage and patch |
|---|---|---|
| `kaggle/flag_extract.py` | `crop_plan` draws crop lengths from the dev-Bangla durations (line 230); `n_crops=3` (line 241) | `f04_v2_ref`: `n_crops=0` |
| `kaggle/build_eval_notebooks.py` | `SPLIT_FILTER = None` = train + every test list (line 93) | `f12_eval_feats` and every FLAG_12-loop stage: `SPLIT_FILTER = ["train"]`, no `dev_set` unpacking |
| `kaggle/build_flag160.py`, `kaggle/build_flag162.py` | lane a = v4 train, v1 / v2 and the four dev lists | `t160a`, `t162a`: `SPLIT_FILTER = ["train"]` (`TRAIN_ONLY`, `release/flag2027_e2e/stages.py:151`); `ngnnguynchn/flag2027-rf092-dev-emb-p` is forbidden |
| `kaggle/vendor_t3enc/t3enc_cell.py` | encodes v4 train, v1 / v2 and the dev lists inside the FLAG_12 loop | `f40_t3enc_mav`: `SPLIT_FILTER = ["train"]` |
| `kaggle/build_e2e_dev_bundle.py` | packs dev pair ids, features, scores, the submitted dev zips and dev T3 streams | `safe04_lab` imports it only for `safe04_tables()` |
| `BEST/v6_eval/pipeline.py` | CONFIG member `r2mix` (Bangla-length crops, excluded by the team rule) | `e50cc`: `Experiment/E2E/system_v11.py:52` keeps only `s007` and `s010B` |

A notebook regenerated from src/ must get the same train-only patches, and must not attach
`datasets/ngnnguynchn/flag2027-rf092-dev-emb-p`, before use.

## Regenerating a notebook with a builder

Builders write notebooks next to themselves (`kaggle/FLAG_*.ipynb`) and read inputs that are not in src/. Copy src/ to
a scratch folder, place the inputs listed under `not_copied` at their original relative paths (each data entry gives
its artifact code in `configs/data_map.json` and its folder under `FF_DATA`, or says that it has no home there), apply
the patches above, then run the builder there. A regenerated notebook is not expected to be byte-identical to the
executed one, because builders changed after the runs; compare the embedded code members instead (`executed_versions`).
Some builders cannot run from src/ alone by design: `kaggle/build_flag163.py` embeds the organisers'
`Input/meta_file_train_set.csv`, `kaggle/build_flag110.py` (and 111 / 112 / 167 / 174, which reuse its code blob) embeds
a dev-set score zip, and `kaggle/build_e2e_v11.py` embeds dev reference zips and four learned fuser files (frozen inputs
embedded in the executed `e50cc` notebook; no producing stage in this repository). `release/factor_enfuse/make_package.py`
and `release/flag2027_e2e/pull_runs.py` import the excluded `kaggle/kapi.py` at top level and cannot run, not even with
`--help`; use `kaggle kernels pull` as described in `tools/PULL_MISSING_RUNS.md`.

## What is not here

By rule: data, features, checkpoints and learned fusers, dev-set files and dev score zips, the organisers' files,
anything derived from VoxBlink, the Kaggle API wrapper `kaggle/kapi.py` and every credential. `not_copied` lists each
reference found in the copied code that was deliberately left out, with its class and reason. The executed notebooks in
`stages/*/original/` are stored without the dev score zip and the organisers' `meta_file_train_set.csv` that some of them
embedded (the stage packages removed them; see each `SOURCE.json`; the scan finds neither payload).

Two identities that appear in both MAV-Celeb v1 / v2 and MAV-Celeb v4 are hard-coded as an overlap list in
`BEST/v7_safe/safe_lib.py:23` and `kaggle/build_l0_notebooks.py:92, :1309`. F1s' applies this list, so the code is kept
verbatim; publishing this identity linkage waits for the team's decision before the repository is made public.

## Files added beyond the design list

The design list (DESIGN section 9.4) has 141 files. 37 more were added because a listed builder cannot run without them:
modules it imports (for example `kaggle/build_rep_notebooks.py`), files it reads at import time

## Provenance log

`kaggle/kapi_runs.reduced.jsonl`: one JSON line per FLAG 2027 Kaggle push, dataset upload or dataset privatize action
made with the team's tool, reduced from the team file `kaggle/kapi_runs.jsonl`. Records of other projects and records
without a kernel, dataset or privatized id are dropped (`derived[].record_filter`; counts in `records`,
`records_in_source`, `records_dropped`). `line` is the line number in the original log (design documents cite it as
`kapi_runs.jsonl:<line>`; every line cited in `stages/` is kept). Kept: kernel or dataset id, time, account, notebook
md5, attached datasets and kernels, GPU flag, smoke settings, secret names (never values), upload files, the id of a
privatized dataset. Dropped: the dataset-sharing audit results (`anonymous_http`, `readers`, `other_can_read`). Local
folders in `source` / `files` are rewritten to repository-relative paths or neutral placeholders (`<scratchpad>/`,
`<temp>/`, `<team-drive>/`, ...; `derived[].path_rewrite`). To identify the exact notebook of a run, take the last push of
its kernel id and compare `notebook_md5`. The records name the Kaggle accounts of the team members that ran the
notebooks.

## Line endings

83 copies use CRLF line endings, as in the team repository. `src/.gitattributes` turns off line-ending conversion so
that git keeps the exact bytes; every sha256 is computed on those bytes. Do not re-save these files with an editor that
changes line endings. Five copies contain a local scratch-folder default path of the team machine
(`summary.copies_with_local_home_paths`); they are kept verbatim.

## Checks and tools

- `python src/_tools/verify_src.py`: every listed file present with the recorded sha256, no unlisted file.
- `python src/_tools/verify_src.py --against <team repository>` (team side): are the copies still identical to the source?
- `python src/_tools/scan_stage_code.py [--out <file>]`: compares the copies with the executed copies under `stages/`
  (read-only; anyone can run it from the published repository).
- `src/_tools/build_src_copy.py` with `src/_tools/src_curation.json` (team side) regenerates this folder, runs the scan
  (`_tools/stage_code_scan.json`) and writes the manifest.
